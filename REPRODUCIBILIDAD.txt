3. PREPARAR EL ENTORNO

3.1 Descargar el repositorio

  git clone https://github.com/pitirringo/futbol-apuestas.git
  cd futbol-apuestas

3.2 Confirmar que los datos no han cambiado

Cada archivo tiene una "huella" que cambia en cuanto se
modifica un solo carácter. Puedes calcularla así:

  En Linux:
    sha256sum Codigo/proyecto_mod_8/E0_consolidado.csv \
              Codigo/proyecto_mod_8/premier_training_data.csv

  En macOS, el comando es shasum -a 256 seguido de los mismos archivos.

  En Windows (PowerShell):
    Get-FileHash Codigo\proyecto_mod_8\E0_consolidado.csv -Algorithm SHA256
    Get-FileHash Codigo\proyecto_mod_8\premier_training_data.csv -Algorithm SHA256

Deberías obtener:

  E0_consolidado.csv         7cea84b123c6924f453463fe3e6936631a87ecc469e2eed649f0c1874bb48e33
  premier_training_data.csv  37de4c4cab439e7448f567eb722476885a7770ab53ffcc561b6a70ffbb5c3aa8

Si no coinciden, el archivo se modificó en algún momento. Lo más común
es haberlo abierto y guardado en Excel, que cambia el formato de las
fechas y los decimales. En ese caso, vuelve a descargarlo del
repositorio y evita guardar los CSV desde Excel.

3.3 Crear un entorno virtual con Python 3.10

Un entorno virtual mantiene los paquetes del proyecto separados del
resto de tu computadora, para que otras versiones no interfieran.

  En Linux o macOS:
    python3.10 -m venv .venv
    source .venv/bin/activate

  En Windows (PowerShell):
    py -3.10 -m venv .venv
    .venv\Scripts\Activate.ps1

  Si prefieres conda:
    conda create -n futbol python=3.10 -y
    conda activate futbol

3.4 Instalar los paquetes

  python -m pip install --upgrade pip
  pip install -r Dashboard-o-pagina/requirements.txt
  pip install nbconvert matplotlib

3.5 Instalar Quarto y comprobar que funciona

Después de instalar Quarto 1.8.25, ejecuta:

  quarto --version          (debe mostrar 1.8.25)
  quarto check jupyter      (debe reconocer el Python del entorno)


4. REPRODUCIR EL ANÁLISIS (Analisis.ipynb)

El notebook tiene que ejecutarse desde su propia carpeta, porque busca
E0_consolidado.csv y wc_predictor.py en ese mismo lugar.

La forma más segura es hacerlo desde la terminal, porque así todas las
celdas corren en orden, de principio a fin:

  cd Codigo/proyecto_mod_8
  jupyter nbconvert --to notebook --execute Analisis.ipynb \
          --output Analisis_ejecutado.ipynb \
          --ExecutePreprocessor.timeout=3600

Si prefieres Jupyter o VS Code, abre Codigo/proyecto_mod_8/Analisis.ipynb,
elige el kernel del entorno .venv y usa "Restart Kernel and Run All
Cells". Conviene no ejecutar celdas sueltas ni en desorden, porque
algunas dependen de variables creadas en celdas anteriores.

El análisis no tiene ningún componente aleatorio: los datos se dividen
por fecha y los modelos de Poisson se estiman con un método
determinista. Por eso no hace falta fijar una semilla, y cada ejecución
da exactamente los mismos números.

4.2 (Opcional) Comprobar que premier_training_data.csv se genera igual

El notebook construye una tabla llamada training_data, y el tablero usa
esa misma tabla guardada como premier_training_data.csv. Para comprobar
que son idénticas, agrega esta celda al final del notebook y ejecútalo
completo:

    import pandas as pd
    ref = pd.read_csv("premier_training_data.csv", parse_dates=["Date"])
    nuevo = training_data[ref.columns].reset_index(drop=True)
    pd.testing.assert_frame_equal(nuevo, ref, check_exact=False,
                                  rtol=1e-9, check_dtype=False)
    print("OK", ref.shape)

Si todo está bien, verás el mensaje OK (2696, 24). Si quieres volver a
generar el archivo, basta con quitar el comentario del bloque
training_data.to_csv(...) que ya está en el notebook.

4.3 (Opcional) Repetir la búsqueda completa de hiperparámetros

Para que el notebook corra rápido, sólo evalúa los valores que
terminamos eligiendo: K_Elo = 15 y k_shrinkage = 0. Si quieres repetir
la búsqueda completa, cambia estas dos líneas en la celda de
configuración:

    K_ELO_CANDIDATOS = [15]          por  [15, 20, 25, 30, 35, 40, 45]
    K_SHRINKAGE_CANDIDATOS = [0]     por  [0, 5, 10, 15, 20]

Eso da 35 combinaciones y puede tardar varias decenas de minutos. Al
final, el notebook debería volver a elegir K = 15 y k = 0.

5. REPRODUCIR EL TABLERO (Dashboard-o-pagina)

Desde la carpeta principal del repositorio, y con el entorno activado:

  En Linux o macOS:
    export QUARTO_PYTHON="$(which python)"
    quarto render Dashboard-o-pagina

  En Windows (PowerShell):
    $env:QUARTO_PYTHON = (Get-Command python).Source
    quarto render Dashboard-o-pagina

El tablero queda en Dashboard-o-pagina/_site/index.html y se abre con
cualquier navegador.

Algunos detalles útiles:

- La variable QUARTO_PYTHON le indica a Quarto qué Python usar. Si no se
  define, Quarto puede tomar otro Python instalado en la computadora, y
  ésa es la causa más común de errores como "module not found".
- El tablero no copia cifras a mano: datos_dashboard.py las vuelve a
  calcular a partir de los archivos de Codigo/proyecto_mod_8. Si mueves
  esa carpeta, indica su nueva ubicación con la variable RUTA_CODIGO,
  por ejemplo:
    export RUTA_CODIGO=/ruta/a/proyecto_mod_8
- La carpeta _site/ se genera cada vez y no se sube a GitHub (está en
  .gitignore).

5.1 Publicación automática en GitHub Pages

Cada vez que alguien sube cambios a la rama main, GitHub repite este
mismo paso en un servidor limpio (Ubuntu, Python 3.10 y Quarto 1.8.25)
siguiendo el archivo .github/workflows/publicar-dashboard.yml, y publica
el resultado en https://pitirringo.github.io/futbol-apuestas/.

Si trabajas en una copia propia del repositorio (un fork), activa la
publicación en Settings > Pages > Source: "GitHub Actions". También
puedes lanzarla a mano desde la pestaña Actions con "Run workflow".

Este proceso funciona, además, como una prueba de reproducibilidad: si
el tablero no se puede construir en una máquina nueva, no se publica.

6.3 Por qué este paso no garantiza exactamente la misma base

Hay tres razones:

- La temporada 2026/27 sigue en curso y Football-Data actualiza su
  archivo cada semana. Nuestra versión llega hasta el 14/09/2026
  (40 partidos de esa temporada). Para obtener la misma base, hay que
  quedarse sólo con los partidos hasta esa fecha, por ejemplo con esta
  línea después de unir los archivos:

      df_consolidado = df_consolidado[
          pd.to_datetime(df_consolidado["Date"], format="mixed",
                         dayfirst=True) <= "2026-09-14"]

- De vez en cuando, Football-Data corrige datos de temporadas pasadas
  (cuotas, árbitros o xG), así que una descarga futura podría diferir en
  algún valor.

- El periodo de prueba del análisis empieza el 01/08/2025 pero no tiene
  fecha de cierre. Si se agregan partidos nuevos, cambian las cifras de
  prueba, la comparación con el mercado y el tablero.

Por eso, para reproducir los resultados que reportamos, la referencia
es el E0_consolidado.csv incluido en el repositorio, cuya huella puedes
comprobar en el paso 3.2. Este paso 6 sirve para revisar cómo se
construyó esa base, no para reemplazarla.
